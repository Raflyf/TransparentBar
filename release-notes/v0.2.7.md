## TransparentBar v0.2.7

Deep RAM, CPU, and GPU/DWM optimization pass across the host process, maximized-window connector, and Explorer XAML bridge, bundled with comprehensive process, IPC, and WinHTTP security hardening.

### What comes bundled:
- **transparentbar.exe** - Native Windows host application (x64)
- **transparentbar_bridge-0.2.7.dll** - Native taskbar transparency bridge
- **Windows installer** (`TransparentBar-setup-v0.2.7.msi`) - Per-user MSI installation
- **Portable ZIP** (`TransparentBar-windows-x64-v0.2.7.zip`) - Application, bridge, build provenance, and SHA-256 sums

---

### Performance & resource optimizations in 0.2.7:

- **Host RAM & binary footprint reduction**
  - Trims cold startup, WinHTTP/TLS, and post-hide pages via `SetProcessWorkingSetSizeEx` (idle private working set reduced from `1.36 MB` to `0.45 MB` and total working set from `11.47 MB` to `2.09 MB`).
  - Loads the tray icon directly from the embedded PE icon resource on MSVC builds, removing the duplicate 89 KB icon payload from `.rdata` (`transparentbar.exe` reduced from `554.0 KB` to `501.5 KB`).
  - Defers `WS_EX_LAYERED` connector window creation until an eligible maximized window is active, releases overlay resources and shrinks internal buffers on hide/disable, and reduces background worker thread stacks to 256 KB.
  - Automatically caps `%LOCALAPPDATA%\TransparentBar\startup.log` at 64 KB on launch.

- **CPU & event-loop overhead reduction**
  - Fixed a timer-tracking bug where foreground focus wakes left the connector OS timer stuck at `16 ms` (`62.5 Hz`) even on an idle desktop.
  - Eliminated per-tick Registry reads (`TaskbarPattern`, `ReduceMotion`), per-tick `FindWindowW` lookups in WinEvent hooks, per-tick `GetProcAddress("GetDpiForWindow")` calls, and per-tick UTF-16 `String` allocations in `maximised_above`.
  - Disables `REFRESH_TIMER_ID` wakeups on foreground changes once the Windows 11 XAML bridge is ready, unhooks `EVENT_OBJECT_LOCATIONCHANGE` when the connector is disabled, and filters non-maximized window drags.
  - Rewrote `smooth_scanline`, `blend_toward`, and `fill_gradient_columns` with zero-allocation buffer reuse, row-major cache-friendly accumulation, bit-exact integer blending/premultiplication, and per-row L1 lookup tables (`51.2%` faster active frames, `0` heap allocations/frame vs `67.2 KB/frame` in `v0.2.6`, and `97.1%` faster static-frame skip).

- **GPU & DWM compositor load reduction**
  - Added a quiescent `250 ms` backoff tier for completely static maximized windows (`75%` fewer `BitBlt` GPU-to-CPU readbacks than `v0.2.6`'s continuous `64 ms` loop).
  - Eliminated redundant `SetWindowPos` DWM layout/z-order commits when geometry, visibility, and z-order are unchanged (`100%` reduction while static).

- **Explorer XAML bridge optimization**
  - Zero-copy UTF-16 `BSTR` element classification removes two heap `String` allocations per `OnVisualTreeChange` callback inside `explorer.exe`.
  - Prunes resolved and root-attached non-taskbar `pending` entries, skips `AgileReference::resolve()` and mutex locks on steady-state callbacks, and only signals `Ready` on state changes (`229x` faster callback processing with `99.97%` fewer allocations).

- **Security hardening**
  - Process mitigations (`SetDefaultDllDirectories`, `SetDllDirectoryW`, Extension Point Disable, Image Load Policy, `/DEPENDENTLOADFLAG:0x800`, `/CETCOMPAT`, Control Flow Guard).
  - Strict Explorer process verification, TOCTOU-hardened bridge DLL handle locking, owner SID and PE version verification, CSPRNG session tokens, and owner-only SDDL DACLs on IPC objects.
  - Hardened WinHTTP update checks (TLS 1.2/1.3, SSL revocation checking, redirects disabled, high autologon security) and `catch_unwind` FFI boundaries in the Explorer bridge.
