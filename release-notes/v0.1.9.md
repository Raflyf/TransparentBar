## TransparentBar v0.1.9

Fixes connector colors that looked shifted or arrived one scroll late on displays using Windows display scaling (for example 125%).

### Fixed
- TransparentBar now declares per-monitor DPI awareness at startup, so window geometry and screen capture use the same device pixels. Previously a scaled display reported a smaller logical taskbar rectangle while capture stayed in physical pixels, which read rows well above the real window edge. That is why the sampled band and the visible color disagreed, and why new content only appeared after one more scroll moved it upward into the wrong band.
- Connector strip height, seam overlap, sample rows, blur radius, frame overhang, and edge slack now derive from the monitor DPI of the taskbar instead of fixed 96-DPI constants. Sizes follow the display rather than any hardcoded scale factor, so other resolutions and scaling levels stay proportional.
- The docked-window tolerance scales with DPI too. A maximized window's invisible resize frame grows with scaling, so the previous fixed 14 px allowance could reject a maximized window at higher scale factors.
- `GetDpiForWindow` and `SetProcessDpiAwarenessContext` are resolved at runtime, so the binary still starts on Windows versions without them and falls back to system DPI awareness.

### Verified
- New native tests cover the scaling table, DPI-independent docking decisions across 96-288 DPI, and that the process really runs per-monitor aware v2. Existing connector, timer, tray, protocol, and updater tests still pass: 15 host tests and 7 bridge tests.

### Unchanged
Connector profile proportions, per-column edge sampling, the 120 ms active refresh with 1000 ms idle eligibility probe, fullscreen suppression, the tray toggle, English UI, system-themed menu, update dialogs, startup settings, and taskbar restoration.

### Limitations
- Colors remain a smoothed approximation of a thin visible screen edge; text, tooltips, protected content, HDR, and display color processing can still affect the sample.
- Connector support is still limited to the primary bottom-docked taskbar with auto-hide off.
- Native tests do not prove visual behavior on every monitor layout. Binaries remain unsigned.
