## TransparentBar v0.2.0

Replaces the v0.1.10 release number with v0.2.0 as requested. This release carries the same connector changes; it does not add another scrolling or animation fix. The old v0.1.10 release and tag are withdrawn after this release is published, while its commit remains in Git history.

### Included connector changes
- Active edge sampling uses a 60 ms timer instead of the earlier 120 ms interval. This is a requested timer interval, not a guaranteed display latency or real-time frame rate.
- Sampled rows have increasing weights toward the bottom of the captured band. This gives nearby edge colors more influence; the capture band still ends above the connector overlay and does not include the final overlapped application rows.
- Each color update blends 30% of the remaining RGB difference toward the latest per-column sample, rather than replacing the displayed colors immediately. This eases color changes but also introduces a short settling delay. First appearance is immediate; disabling the connector and fullscreen suppression still hide it immediately.
- Connector height is 34 px at 96 DPI, reduced from 42 px, and scales with the taskbar monitor DPI.

### Version synchronization
Cargo package and lockfile, Windows file/product resources, installer, About dialog, bridge DLL filename, and shared status mapping now use 0.2.0. No dependencies or connector behavior changed relative to v0.1.10.

### Retained behavior and limitations
- Per-monitor DPI awareness, native English tray UI, system-themed menu, manual connector toggle, startup settings, update dialogs, and taskbar restoration remain in place.
- An enabled inactive connector checks eligibility once per second without pixel capture. Disabling it stops that timer.
- Connector support remains limited to the primary bottom-docked taskbar with auto-hide off. Screen-edge sampling is an approximation and can be affected by text, tooltips, protected content, HDR, and display color processing.
- Automated tests do not establish visual smoothness or scrolling synchronization on every desktop. No user-desktop visual validation is claimed. Binaries remain unsigned.
